# 缓存TTL 设计与接入规范

## 1. 配置说明

- 配置名称：`缓存TTL`
- 展示位置：前端设置页
- 存储键：
  - 当前键：`cacheTtlMinutes`
  - 兼容旧键：`homeSectionTtlMinutes`（仅用于历史配置迁移读取）
- 单位：分钟
- 默认值：`10`

`缓存TTL` 表示页面数据缓存允许保留的最长时长。页面命中缓存时优先直接渲染，若缓存年龄超过 TTL，则在后台异步请求最新数据并静默刷新页面内容。

## 2. 当前已接入页面

### 2.1 专辑页

- 缓存粒度：按分页缓存，`pageIndex -> AlbumPageCacheEntry`
- 缓存内容：
  - `albums`
  - `lastUpdatedSecs`
  - `hasNextPage`
- 访问流程：
  1. 进入专辑页或切换分页时，先检查当前页是否已有缓存
  2. 若命中缓存，立即渲染，提供秒开体验
  3. 若缓存过期，则后台调用 `getAlbums2` 刷新
  4. 若刷新成功，仅更新当前页缓存并静默替换 UI
  5. 若刷新失败，保留旧缓存，不打断浏览
- 防重复策略：
  - `m_albumPageInFlight` 防止同一页重复发请求
  - 专门的 `albumsFailed(offset, size, error)` 信号用于释放失败状态

### 2.2 艺术家页

- 缓存粒度：整页列表缓存
- 缓存内容：
  - `m_artistCache`
  - `m_artistCacheLastUpdatedSecs`
- 访问流程：
  1. 进入艺术家页时先尝试渲染缓存
  2. 若缓存过期，则后台调用 `getArtists`
  3. 请求成功后更新缓存并静默刷新表格
  4. 请求失败时保留旧缓存
- 防重复策略：
  - `m_artistRequestInFlight` 防止重复请求
  - `artistsFailed(error)` 信号用于失败回收

### 2.3 主页

- 四个模块共用统一的 `缓存TTL`
- 若模块已有缓存且未过期，则不重复进入 loading
- 若模块缓存已过期，则后台刷新；只有首次无缓存时才展示 loading

## 3. TTL 校验工具

当前统一通过主窗口中的 TTL 判定工具完成：

- `MainWindow::isCacheExpired(qint64 lastUpdatedSecs) const`

它基于全局的 `m_cacheTtlSecs` 进行校验，专辑页、艺术家页共用同一套规则，保证行为一致。

## 4. 后续新增页面接入规范

后续任意新页面若需要接入统一缓存机制，建议遵循以下规范：

1. 在页面所属控制层维护缓存数据与 `lastUpdatedSecs`
2. 页面打开时优先渲染缓存，不阻塞 UI
3. 统一调用 `isCacheExpired(...)` 判断是否需要后台刷新
4. 为该页面维护独立的 `in-flight` 标记，避免重复请求
5. 请求失败时不要清空旧缓存，优先保留最后一次成功结果
6. 若接口存在分页，缓存粒度应按页或按查询条件拆分
7. 新页面如需特殊 TTL，不应单独硬编码，而应在统一 `缓存TTL` 基础上扩展配置说明

## 5. 验证建议

建议至少覆盖以下 TTL 阈值进行验证：

- `5 分钟`
- `30 分钟`
- `60 分钟`

重点检查：

- 命中缓存时是否立即渲染
- 过期后是否仅在后台刷新
- 同页重复访问是否避免无效重复请求
- 刷新失败时是否保留旧数据
- 页面切换过程中是否无明显卡顿或闪烁
